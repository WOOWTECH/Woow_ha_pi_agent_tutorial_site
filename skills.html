WoowTech Skill 手冊

裝一顆 Skill，Pi Agent 立刻多會一件事

Skill 是給 AI 看的「工作手冊」：一個資料夾、一份 SKILL.md，裝進去它就會照著做。這本手冊幫你把網路上最熱門的開源 skill 挑好、講清楚、附上安裝指令——先裝別人做好的，再學著寫自己的。

調查基準：本冊的集合規模與維護狀態為 2026-08-20 調查當日的 GitHub 公開數據，會隨時間變動；安裝前建議點進原始 repo 再確認一次。

Skill 是什麼，為什麼要裝

把 Pi Agent 想成一位很聰明的萬事通助理：什麼都能聊，但「你家的做事方法」它不會通靈。Skill 就是教鐘點阿姨的工作手冊——把「遇到什麼情況、照什麼步驟做」寫成一份 Markdown，放進技能資料夾，它遇到對應情況就會翻出來照做。

  • 裝別人寫好的：文件處理、簡報、研究、設計……開源社群已經寫好上千顆，裝了就會。
  • 之後寫自己的：家裡的獨門流程（出週報、冰箱盤點）也能包成 skill，做法見第 16 章。

Skill 的原理（怎麼被掃描、怎麼進 system prompt、AI 怎麼決定用不用）在第 14 章有完整說明，這本手冊專注在「挑哪些、怎麼裝」。

怎麼裝（3 分鐘版）

完整圖解在第 15 章，這裡是速查版：

  1. 打開 pi-web 的 Skills 面板

    HA 側邊欄 → Pi Agent 工作區 → 切到 Skills 面板。

  2. 貼上 package spec，按 Install

    本冊每個項目都附好可以直接貼的 spec。合法寫法：

    # GitHub repo（最常用）
git:github.com/anthropics/skills
# 釘住版本（tag 或 commit，建議正式環境用）
git:github.com/anthropics/skills@v1.2.0
# npm 套件
npm:@scope/some-skill
# 本地路徑（自己寫的 skill）
/data/pi-agent/skills/my-skill

  3. Reload session 驗證

    裝完按 Reload session（或開新 session），問它「目前載入了哪些 skill？」確認有進到清單。

  4. 用一句話觸發測試

    照該 skill 的 description 講一個對應需求，確認它真的會拿出來用。

提示：多 skill 的 monorepo（例如 anthropics/skills）整包裝進去，Pi 會遞迴掃描全部 SKILL.md。只想要其中一顆時，實務做法是 clone 下來後用本地路徑指向那個子資料夾——git spec 目前沒有「只裝子目錄」的語法。

相容性須知

SKILL.md 規格已被 Claude Code、Codex、Gemini CLI、Cursor、OpenCode 與 Pi 等採用，純 Markdown 的 skill 幾乎到處能跑。會「退化」的只有三種情況：

  • 依賴 Claude Code 專屬機制（hooks、plugin 指令、subagent 派工）——skill 本文仍可讀，但自動觸發行為可能不完整。
  • 依賴特定 MCP／SaaS 帳號——沒接那個服務就沒用，裝前看清楚前置需求。
  • scripts/ 需要容器內沒有的 runtime——Woow HA Pi Agent 的容器環境要特別注意這條；純 Markdown skill 相容性最好。
觀念：挑 skill 的第一準則不是星數，是「它假設的環境你有沒有」。

安全守則

注意：Skill 的本質是「餵給 agent 的指令」。裝第三方 skill＝讓一段陌生文字指揮你家的 AI。
  • 先讀後裝：安裝前把 SKILL.md 打開讀一遍，或叫 Pi Agent 先讀給你聽：「先讀這顆 skill 的內容，告訴我它會做什麼、有沒有風險，我同意再裝。」
  • 會動 HA 的先進測試機：像 home-assistant-manager 這類會改線上設定的，先在測試實例驗證。
  • 正式環境釘版本：用 @tag 或 @commit 釘住，避免上游改內容你無感升級。
  • 星數＝人氣，不＝安全：熱門集合一樣要看它拿什麼權限做什麼事。

SKILL.md 規格速查

一顆 skill 的最小骨架（寫自己的 skill 看第 16 章）：

fridge-check/
└── SKILL.md          ← 唯一必要檔案

# SKILL.md 內容
---
name: fridge-check
description: 使用者傳冰箱照片時，列出食材、找出臨期的、建議晚餐菜色。
  也在使用者問「今天煮什麼」「冰箱還有什麼」時觸發。
---

# 冰箱盤點
（給 agent 看的做法說明，寫得像教新同事）
欄位必填說明
name是小寫英數與連字號，1–64 字元。
description是做什麼＋何時用。AI 靠這行決定要不要載入，把使用者會講的話寫進去。
license / compatibility / allowed-tools否授權、相容性標注、工具白名單等選填欄位。

慣例：SKILL.md 保持精簡，附件放 references/、scripts/、assets/，用到才讀，避免吃爆 context。

常見問題

裝了但完全沒反應？
先 Reload session 或開新 session（skill 是 session 開始時載入的）。再問它「目前載入了哪些 skill？」確認有進清單；有進但不觸發，多半是 description 沒涵蓋你的講法——直接點名：「用 ○○ skill 幫我做這件事」。
skill 裝太多會怎樣？
每顆 skill 的名稱與描述都會佔 system prompt 的 context，裝幾十包會讓 AI 分心也變貴。原則：常用的留著，試玩過不用的就移除。
怎麼更新、怎麼移除？
Skills 面板可直接移除；git 來源沒釘版本時重新安裝會抓最新，正式環境建議 @tag 釘住、要升級時自己改 tag。詳見第 15 章。
附 scripts 的 skill 在 add-on 容器跑不動？
先確認容器內有沒有該 runtime（Python 套件、Node 等）。跑不動不代表 skill 全廢——Markdown 部分的知識還是會被 AI 用上；真的需要 scripts 的，挑純 Markdown 的替代品通常更省事。
可以只裝 monorepo 裡的其中一顆嗎？
git spec 目前沒有子目錄語法。實務做法：clone 到本機，把想要的那顆 skill 資料夾放到 /data/pi-agent/skills/，或用本地路徑安裝。
