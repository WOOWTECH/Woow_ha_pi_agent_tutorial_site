第 15 章

從 GitHub 裝別人做好的 Skill

上一章講完 Skill 是什麼，這一章直接動手。教你打開 Skills 面板、貼上一個 GitHub 網址、按下裝、看它出現在系統提示裡。做完你的 AI 就多了那項新本事，全程不用寫程式、也不用 SSH 進 HA 主機——按幾下滑鼠就搞定。

為什麼第一件事是「裝別人做好的」

第 14 章把 Skill 講成「教 AI 一項專門手藝」，也提到「網路上很多人已經幫你把手藝寫好，塞進 GitHub 上等你去撿」。那一章講的是概念，這一章告訴你怎麼撿。

從別人的 skill 裝起有三個好處：

  • 不用會寫程式——skill 就是一個資料夾＋一份 SKILL.md 說明書，寫的人已經打包好，你只需要「貼網址、按裝」兩步。
  • 先體驗才知道值不值——與其花一小時看範例學怎麼寫，不如花三分鐘裝一個現成的，用它一個下午確認 Skill 這套機制是不是你要的，再決定要不要投入時間自己寫（第 16 章會教）。
  • 看好作品當教材——你裝進來的 skill，其實就是一份「別人怎麼寫 SKILL.md」的活範例。之後要自己寫的時候，去 /data/pi-agent/skills/ 底下打開 SKILL.md 抄結構抄語氣，比看空白模板快十倍。

還有一個容易被忽略的動機：Skill 是 Pi Agent 生態系的核心，而不是可有可無的花邊。同一顆 AI 大腦（例如 GLM-4.6），有沒有裝對 skill，做同一件事的結果會差很多。裝了 home-assistant-best-practices 之後，AI 幫你寫自動化會直接跟你講「這裡用 helper 比 template sensor 好」；沒裝的話，AI 會用它自己（可能過時的）習慣硬寫。這不是誰比較聰明的問題，是「有沒有把家裡的規則告訴它」的問題。

觀念：裝 skill 之於 AI，等於裝 HACS integration 之於 HA。原廠有東西可以用，但生態系裡總有更貼近你需求的社群作品——會挑會裝的人，可以直接跳過原廠的粗糙預設，用到大家幫你磨過的成品。

Skill 的三種來源

Pi Agent 的 Skills 面板可以吃三種來源，寫在同一個輸入框裡：

來源寫法範例它會怎麼處理這章教嗎
GitHub 完整 URL https://github.com/mattpocock/skills 直接 git clone 會，主力示範
owner/repo 縮寫 mattpocock/skills 自動補成 https://github.com/mattpocock/skills，再 clone 會，第二節示範
本地資料夾路徑 /data/pi-agent/skills/my-first-skill 直接讀那個資料夾（不 clone） 不會，留到第 16 章自己寫的時候

三種背後其實只有一個運作邏輯：把某個資料夾放到 /data/pi-agent/skills/ 底下，然後 pi-web 每次開新 session 就去掃這個資料夾、把裡面每個子資料夾當一個 skill。差別只在「這個資料夾怎麼來的」——遠端拉下來的、還是你自己丟進去的。

提示：第三種（本地路徑）是留給「你自己在電腦上寫了半個小時的 skill、想先塞進去試試」的情境。它跳過 git 這一層，改動不用 push 也能生效。這章示範前兩種，因為對「還沒開始寫 skill」的人來說，是最實用的入手方式。

Pi Agent 是怎麼下載這些 skill 的

知道背後在跑什麼，會讓你比較安心，也在出事的時候比較好排查。Pi Agent 拉遠端 skill 的方式很傳統：就是 git clone。

從 v0.12.0 版開始，Pi Agent 的 add-on 基底映像有預裝 git 跟 openssh-client 兩個套件（這件事寫在 Containerfile 的 apt-get install 那行），所以你按下「Add Skill」的當下，容器裡真的在跑一句類似這樣的指令：

cd /data/pi-agent/skills/
git clone https://github.com/mattpocock/skills.git mattpocock-skills

然後 pi-web 就會在下一次開 session 的時候，讀到 /data/pi-agent/skills/mattpocock-skills/ 這個資料夾，把它註冊成一個可用的 skill 集合。你在 UI 上其實是在做「git clone 的圖形化版本」，這點知道之後很多疑問就自然消解了：

  • 為什麼要 GitHub URL？因為 git clone 吃 URL。
  • 為什麼私人 repo 不會通？因為 git clone 遇到私人 repo 要問你帳號密碼，UI 沒地方讓你填。
  • 為什麼裝了不會自動更新？因為 clone 完就完了，除非你手動再 git pull（UI 沒這個按鈕，只能移除重裝）。
  • 為什麼 clone 一半可以中斷？因為那就是一個網路操作，你把頁面關掉、網路斷線，跟你在終端機 Ctrl+C 中斷 git clone 一樣。
觀念：Pi Agent 把 /data/pi-agent/skills/ 這個資料夾當作 skill 的家（詳細目錄結構見第 20 章）。這個資料夾在 HA snapshot 備份的時候會一起被打包，主機還原後你的 skill 收藏也會回來，不用重裝一次。

動手裝一個真實 skill

我們用一個常見的公開 repo 當示範：mattpocock/skills（Matt Pocock 是 TypeScript 圈的知名教學者，這個 repo 是他公開的 skill 集合）。它跟家庭情境沒直接關，但它是個「絕對裝得起來」的 baseline，用來讓你熟悉流程剛剛好。

  1. 打開 Pi Agent 工作區

    從 Home Assistant 側邊欄點「Pi Agent」進到主介面（第 3 章教過的路徑）。你會看到左邊是 Session 列表、中間是對話區、右上有一排小圖示——那排小圖示就是面板切換列。

  2. 點右上「工具箱」圖示打開 Skills 面板

    右上工具列由左至右通常是：Models（模型）、Skills（技能，圖示是一個工具箱或積木）、System prompt（唯讀）、Settings（設定）。滑鼠移上去 tooltip 會顯示名字，找到「Skills」點下去。畫面右側會滑出一個側欄，最上面通常是「Add Skill」或「＋」按鈕，下面是已裝的 skill 清單（第一次進去這裡是空的）。

  3. 按「Add Skill」叫出輸入框

    按下「Add Skill」或「＋」按鈕，會跳出一個對話框，裡面有一個輸入框，上方通常寫「GitHub URL / owner/repo / local path」——這就是吃三種來源的那個框。有些版本會分成三個 tab（Remote／Shorthand／Local），有些直接一個框讓你貼什麼都可以，看你 pi-web 的版本而定。

  4. 貼上完整 GitHub URL

    把這行複製貼上：https://github.com/mattpocock/skills。末尾不要加 .git 也沒關係——pi-web 會自動補上。也不用先在瀏覽器打開這個網址檢查——反正一按裝它就會告訴你 repo 存不存在。

  5. 按確認開始 clone

    按「Install」／「Add」／「確認」按鈕（依語言與版本不同）。這時候你會看到一個進度條或轉圈圈符號，狀態文字類似「Cloning...」或「Downloading...」。這一步實際跑的就是我們上一節講的 git clone，時間大約 5-30 秒（看 repo 大小和你網路）。不要按取消也不要重新整理頁面，讓它跑完。

  6. 看到 skill 出現在列表就成了

    完成後對話框關閉，Skills 面板的清單裡多了一個新項目，名字通常就是 repo 名（mattpocock-skills 或 skills）。每個項目旁邊會有一個小小的「三點」選單，可以點進去看細節或移除。裝好了。

  7. 開新 session 驗證 skill 有進到 system prompt

    按左上「New Session」開一個新對話——要開新的，不是留在舊的，因為 system prompt 是 session 開場時就決定好、之後不重讀。然後點右上「System prompt」面板（唯讀的那個），往下捲，你應該能看到一段類似這樣的區塊：<available_skills>...mattpocock-skills...</available_skills>。看到自己剛才裝的 skill 名字有出現，就代表 pi-web 認得它了、AI 也在這個 session 裡「知道」它可以用這項技能。

提示：如果第 7 步的 System prompt 面板裡沒有你剛裝的 skill 名字，不用急著懷疑失敗——先按一下瀏覽器 F5 重新整理再開一個更新的 session。有些 pi-web 版本的前端狀態要重整才刷新（見「troubleshoot」那節）。

owner/repo 縮寫：懶得貼完整網址

剛剛第 4 步你貼了 https://github.com/mattpocock/skills——但其實你可以只貼 mattpocock/skills，Pi Agent 會自動幫你補上前面的 https://github.com/。這種寫法叫做 owner/repo shorthand（作者／repo 名 縮寫）。

兩種寫法會產生完全一樣的結果：

你貼什麼Pi Agent 實際會 clone 什麼
https://github.com/mattpocock/skillshttps://github.com/mattpocock/skills.git
https://github.com/mattpocock/skills.githttps://github.com/mattpocock/skills.git
mattpocock/skillshttps://github.com/mattpocock/skills.git

使用時機很直觀：如果 skill 在 GitHub 上、且是 public repo，就用縮寫；其他情況一律貼完整 URL。

不吃縮寫的情境：

  • Skill 放在 GitLab、Bitbucket、Codeberg 這類非 GitHub 平台——縮寫預設是 GitHub，不會自動判斷。
  • Skill 放在 私人 Gitea／自架 Git server——同理。
  • 你想要指定 特定 branch 或 tag——縮寫只能拉預設分支（通常是 main），要拉別的 branch 需要用完整 URL 加後綴（不同版本 pi-web 語法不一，實務上如果要非 main 分支，一律建議先自己 fork 一份到自己的 GitHub 再裝 main）。
觀念：縮寫語法不是 Pi Agent 發明的，這是 GitHub 生態圈的慣例——gh repo clone owner/repo、npx owner/repo、uvx --from git+github:owner/repo 都吃這種寫法。之所以 GitHub 有這種特權，是因為它是公開開源 repo 事實上的主場，工具都預設先猜 GitHub。

不同來源的差別與踩雷點

裝 skill 看似只是「貼網址、按裝」，但每種來源背後的 auth 機制差很多。這節把各種情境攤開來，讓你選對路。

來源類型 會不會通？ 為什麼 解法
公開 GitHub repo（HTTPS） 會，一貼就通 公開 repo 的 git clone https://... 完全不需要 auth 直接用，這是 90% 的情境
公開 GitHub repo（owner/repo 縮寫） 會，等同上面 Pi Agent 自動補成 HTTPS URL 能用縮寫就用縮寫，貼起來省事
私人 GitHub repo（HTTPS） 不會通 Pi Agent 沒有 UI 讓你填 GitHub 帳號密碼或 PAT（Personal Access Token） 把 repo fork 成 public（如果你有權限）；或在 HA host 上手動 git config --global credential.helper store 先跑一次 clone 快取密碼再用縮寫
私人 GitHub repo（SSH URL：git@github.com:owner/repo） 技術上支援（v0.12.0+ 有 openssh-client），但要自己設定 key SSH 認證要你在 HA host 產一支 SSH key、把 public key 貼到 GitHub Settings → SSH Keys、還要在容器裡 known_hosts 加上 github.com 不推薦——這是為進階使用者留的門，一般家用建議走 fork 成 public 的路線
GitLab／Bitbucket／自架 Git server 的公開 repo 會通，用完整 HTTPS URL 只要 URL 是完整的 https://... 就當一般 git clone 處理 貼完整 URL，不能用縮寫
本地資料夾 會，但要你自己塞進去 Pi Agent 只掃 /data/pi-agent/skills/，不會自己找檔案 SSH 進 HA host 用 scp、rsync、或直接掛 Samba share 丟資料夾進去，第 16 章會教
注意：「有 v0.12.0 就有 openssh-client」不代表 SSH 一定能通——你還要處理 SSH key 產生、GitHub 綁定、known_hosts 授信。這條路一步就 30 分鐘、坑非常多，除非你本來就是走 SSH 管 git 的人，否則強烈建議走「fork 成 public」的路線：如果 skill 是別人的、fork 到自己帳號設 public；如果是自己寫的、放到你自己的 public repo。這樣一輩子都是 90% 情境，直接按裝就通。

裝完 skill 該做的三件事

Skills 面板上多了一列不代表「這就結束了」。認真用一個 skill，還有三件事要做：

  1. 開新 session 測試 skill 有反應

    剛剛第 7 步在 System prompt 看到 skill 名字，只代表 pi-web 「認得」它，還沒證明 AI 真的會用。開一個新 session，用測試句直接點名這個 skill：例如「請你用 skill 名字 幫我做 XX」。AI 如果有回應、有動用工具，就代表 skill 通了。如果 AI 說「我沒看到這個 skill」或直接無視，回頭排查（見「troubleshoot」）。

  2. 讀 skill repo 的 README 搞懂它能做什麼

    裝完最容易忽略的事就是不讀說明書。每個 skill repo 的根目錄一定有 README.md——寫的人會在裡面告訴你：這個 skill 叫什麼、哪些觸發情境會被叫出來、需要哪些工具、有沒有 environment variable 要設。花 5 分鐘讀完，比你在對話裡瞎試半小時有效多了。回到 GitHub repo 的頁面直接看，或 SSH 進 HA host 到 /data/pi-agent/skills/<repo-name>/README.md 打開讀。

  3. 沒幫上忙就移除，別留在那裡佔 tokens

    Skill 只要出現在 <available_skills> 塊裡，就會占用 system prompt 的 tokens——這是每一次對話都要吃的固定成本。用一個星期發現這個 skill 你根本用不到，或者它跟你其他 skill 職能重複，就大方地移除。留著只是花你 API 的錢還讓 system prompt 變雜亂，讓 AI 挑錯 skill 的機率變高。移除方法看下一節。

提示：剛開始玩的時候容易犯的錯是「看到有人推薦的 skill 就全裝」，結果 System prompt 塞了 20 個 skill，AI 每次要挑哪個都想很久。實務建議是先只裝 1-2 個真的會用到的，用熟了再慢慢加，遇到不順再淘汰。

移除 skill 的兩種方式

移除 skill 有兩條路，各有各的場合：

方式 A：從 Skills 面板 UI 刪

打開 Skills 面板（右上工具列的工具箱圖示），找到那個 skill 的列，右邊有一個「三點選單」（⋮）或「垃圾桶」圖示。點下去會跳確認對話框，按確定就會把 /data/pi-agent/skills/<name>/ 整個資料夾刪掉。

這是 99% 的情境該用的方式——按兩下就好，不會刪錯。適合：不想要某個 skill 了、換一個更好的替代、清理實驗留下來的雜項。

方式 B：SSH 進 HA host 用指令刪

UI 掛掉了、或某個 skill 資料夾整個壞掉導致 pi-web 讀不到列表、或你要一次刪很多個——這時候走 terminal：

# SSH 進 HA host（Advanced SSH & Web Terminal add-on）
# 進去 Pi Agent 的 skill 資料夾
cd /data/pi-agent/skills/

# 看有哪些
ls

# 刪掉不要的（可以搭配萬用字元一次多個）
rm -rf mattpocock-skills

# 或用萬用字元刪一整批（例如所有實驗性的）
rm -rf test-*
注意：rm -rf 沒有救回鍵。打指令之前先 ls 一下看你人在哪個資料夾。刪錯了要靠 HA snapshot 還原（第 20 章）。

刪完之後回到 pi-web 開一個新 session，System prompt 面板裡就不會再有那個 skill——因為 pi-web 每次開 session 都是重掃資料夾。舊的 session 不會受影響，它們是在開場時就把 skill 內容嵌進 system prompt 的，之後刪不刪外部檔案跟舊 session 的 context 已經無關。

常見卡關

  1. 貼了 URL 按確認完全沒反應

    三個常見原因：（1）URL 打錯字——最容易的是打成 github.com/xxx 沒有前面的 https://，或 owner 拼錯。開一個新分頁把整段 URL 貼進去看得不得到那個 repo。（2）repo 是 private 或已刪除——公開檢查方式是無痕視窗開那個 URL，看得到就是 public。（3）你剛裝了但沒等 clone 完就跑去看列表——重整頁面，通常已經在了。

  2. 裝到一半跳 fatal 401 或 Authentication failed

    這就是私人 repo的招牌錯誤——Pi Agent 沒有 auth 設定，遇到需要密碼的 repo 就是死路。解法：把 repo fork 成 public（在 GitHub 網頁上 Fork 那顆按鈕、然後到 fork 的 Settings 把 Visibility 改成 Public），然後改裝你 fork 過來的 public 版本。這是為什麼上面「來源對照表」那格特別強調——因為這是新手最常撞的坑，遇到就當「重複別人的 repo 一次」處理，不要糾結 auth 怎麼設。

  3. Clone 明明完成了但 Skills 面板不出現

    先按 F5 重整 pi-web 頁面，通常這一步就解決——有些版本前端 state 沒即時同步。還是不出現的話按 F12 打開瀏覽器 devtools，切到 Console 分頁看有沒有紅字錯誤（大多是 pi-web 前端 bug）。再看看 Network 分頁，找 /api/skills 那個請求——如果它回 4xx 或 5xx，就是後端問題（重啟 Pi Agent add-on 通常會好）。

  4. Skill 裝完了但 AI 好像完全忽略它

    先確認 skill 有進到 System prompt（右上面板往下捲找 <available_skills>）。有的話問題就在觸發強度——這個 skill 的 SKILL.md 裡的 description 寫得太模糊，AI 判斷不出你在做的事情該不該叫它。臨時解法：對話裡直接點名「請用 skill 名字 幫我」。長遠解法：讀那個 skill 的 README 看有沒有「Trigger phrases」建議、或者第 16 章教你怎麼寫更清楚的 description。

  5. Clone 卡在 50%、進度條不動

    網路問題居多。可能是 HA 主機連 GitHub 慢（家裡光世代連 GitHub 偶爾抽風）、或 repo 太大（少數 skill repo 有含大型 asset，數十 MB 起跳）。解法：等 3-5 分鐘看看會不會自己完成。真的太久就取消，改用 SSH 進 HA host 手動下：cd /data/pi-agent/skills/ && git clone https://github.com/xxx/yyy.git——terminal 會顯示每一步的狀態，卡在哪裡看得比 UI 進度條清楚。

  6. 裝進來的 skill 名字重複、跟原有的撞名

    Pi Agent 的 skill 是以資料夾名（也就是 repo 名）為 key 的，如果兩個 repo 都叫 skills（滿常見的），第二個裝進來會蓋掉第一個。解法：SSH 進 HA host，把資料夾手動改名：cd /data/pi-agent/skills/ && mv skills mattpocock-skills，然後 pi-web 開新 session 就會用改過的名字。以後再裝 skill 前先掃一下你的資料夾，避免撞名。

  7. 裝完想更新到最新版

    UI 沒有「更新」按鈕，因為 Pi Agent 不會自動追蹤 upstream。要更新只有一條路：移除、重裝。從 Skills 面板刪、再貼一次 URL 裝進來——這樣拿到的就是當下的最新版。也可以走 SSH 手動 cd /data/pi-agent/skills/<name> && git pull，但這只有你自己記得的時候會做，實務上沒人這樣管。乾脆定期（一個月一次）盤點你留下的 skill，重新裝一遍就好。

  8. Skill 資料夾長超級大、占很多硬碟

    正常 skill 一個資料夾幾百 KB 到幾 MB，如果某個裝完發現 du -sh /data/pi-agent/skills/<name> 是幾百 MB 甚至 GB，通常是 repo 裡包了大型 asset（範例影片、pre-trained model）。看 README 有沒有說明用途——用不到就直接移除，用得到但不想占硬碟就用「本地路徑」方式改裝一份精簡版（把 SKILL.md 和必要的資料夾自己剪一份放進去）。詳見第 16 章。

常見問題

要怎麼找到好用的 skill？有清單可以逛嗎？
目前沒有「Pi Agent 官方 skill 商店」——Skill 是散在各人 GitHub 上的。找法：（1）skills.sh 是社群整理的精選站，可以逛主題分類。（2）GitHub 上直接搜 topic:claude-skill 或 topic:pi-agent-skill。（3）在 Reddit 的 r/ClaudeAI、r/homeassistant、Twitter/X 找 #skills 話題。優先挑跟 HA、smart home、家庭情境相關的——通用型的 skill（例如 general coding、markdown 格式化）對家用場景幫助有限。
裝了 skill 對話品質會變好嗎？
只有在特定情境會變好，日常閒聊沒差。Skill 的價值是「在對的時機幫 AI 補上該知道的規則或工具」，例如你在寫 HA 自動化的時候有 home-assistant-best-practices 就幫很大；但你在問「今天要下雨嗎」這種天氣查詢，一堆 skill 掛在那反而讓 AI 選擇困難。所以裝 skill 是「解決特定痛點」的工具，不是「開了讓 AI 全面變聰明」的魔法。買菜刀不會讓你自動變會做菜，你要真的用它切東西才有意義。
Skill 會不會自動更新？作者改了我這邊也會跟著改嗎？
不會自動更新。你按裝的那一刻，Pi Agent 只是 git clone 了當下的版本到本地，之後作者在 GitHub 改了什麼、發了新 tag，你這邊都不知道。要拿最新版只能移除、重裝（見 troubleshoot 第 7 條）。這個機制是刻意的——避免「你半夜作者 push 了一個 breaking change，你早上起來自動化就爛掉」的情況。你想追新版是主動行為，不是被動接受。
一次可以裝幾個 skill？有沒有上限？
技術上沒有硬性上限——資料夾要多少個都行，硬碟裝得下就好。實務上超過 5-10 個就會開始出問題：System prompt 變超長吃 tokens、AI 挑 skill 挑不定、彼此規則衝突。老手的建議是控制在 3-7 個，且每個都有明確不重疊的職能。與其裝 10 個「不知道什麼時候會用到」的 skill，不如裝 3 個「幾乎每天用」的 skill。
裝了不同 skill 會不會互相衝突或搶著回應？
會，這是裝多之後的典型副作用。舉例：你同時裝了 A skill「教 AI 寫自動化要用 helper」跟 B skill「教 AI 寫自動化直接用 template sensor」，AI 每次收到相關問題會兩邊都想採用，最後不是給你混合物、就是選一邊放棄另一邊。判斷方式：讀你裝的每個 SKILL.md 的 description，看有沒有兩個描述涵蓋一樣的觸發情境。有的話留一個就好。這也是為什麼建議「先只裝 1-2 個用熟再加」。
裝進來的 skill 在哪個實體檔案裡？我想手動偷改一下
位置在 /data/pi-agent/skills/<repo-name>/，這是 HA add-on 容器內的路徑。從 HA host 用 Advanced SSH & Web Terminal add-on 進去，然後 cd 過去就可以看到。每個 skill 一定有 SKILL.md（主要說明書），可能有 references/（額外參考）、scripts/（腳本）等資料夾。手動改是允許的——但下次移除重裝就會被覆蓋，所以偷改屬於「臨時實驗」用法，長期想改就 fork 成自己的 repo 再改再裝。
把 API 費用花在 skill 上值不值？
Skill 本身不會多收你錢——它只是幾份 markdown 檔案，被塞進 system prompt 而已。多花的錢在「系統提示變長」——每一輪對話的 input tokens 都多算了幾百到幾千個 tokens（看 skill 大小）。以 GLM-4.6 這種便宜模型算，一個 skill 每對話多花不到 0.001 美金。你如果一天對話 100 輪，一個月頂多多 3 美金。省的話：只留真的用到的 skill、避免超長 skill（超過 5000 字的通常寫太細）、日常小事切非 reasoning 模型（第 12 章）。
可以把 skill 的資料夾複製到另一台 Pi Agent 用嗎？
可以，這也是離線遷移的正規做法。從 A 主機把 /data/pi-agent/skills/<name> 整個 tar 打包，傳到 B 主機同路徑解開，B 主機的 pi-web 開新 session 就會認到。不用透過 GitHub、不需要網路。這在你搬家換 HA 主機、或者從測試機搬到正式機的時候超好用。備份的話直接用 HA snapshot 更省事——第 20 章會講到 /data/pi-agent/ 整個目錄會被 snapshot 涵蓋。
還是遇到怪問題怎麼辦？
先翻第 22 章卡關手冊，它把常見症狀跟解法做了完整索引，包含 Skill 裝不起來的專節。還是找不到就把「你貼的 URL」「錯誤截圖」「pi-web 版本」貼到 GitHub issue 或 Discord 社群。不要只講「裝不起來」——附上你點了什麼、看到什麼、System prompt 有沒有東西，別人才有可能幫得上忙。這也是為什麼建議前面的 troubleshoot 你都要親自跑過一輪。
